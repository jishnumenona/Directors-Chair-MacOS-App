2026-08-06 · Ten views × six dimensions · measured against a 300-scene / 3,600-shot production and a 600-scene / 7,200-shot blockbuster-scale board · benchmark class: Logic Pro, Final Cut Pro, DaVinci Resolve, Premiere Pro

Executive verdict

The foundations are genuinely professional-grade: atomic writes with backups, a 1,726-test suite with real UI-automation journeys and VoiceOver traversal checks, deterministic stress fixtures, and — after the three audits of this program — measured, guarded performance at blockbuster scale with no crashes and no super-linear cost growth anywhere. What separates this from the Logic / FCP / Resolve class today is not raw speed. It is a short list of platform-grade guarantees those apps treat as table stakes: continuous autosave, universal undo, document versioning, a proxy-based media pipeline, and interchange formats — plus depth of test coverage outside the script editor.

Method

Every number below is measured, not estimated: each view is mounted through the real CentralViewRouter (real coordinator, project view-model, timeline) against deterministic stress projects (StressProjectGenerator, fixed seed), timing cold mount and the cost of one whole-project publish while frontmost (BigProjectViewAuditTests, runs on every verify). Debug build; thermal variance ±50%, so grades key off orders of magnitude. An Avengers-class breakdown runs to a few thousand VFX shots; the 7,200-shot board deliberately overshoots it.

Robustness & test estate

  • Persistence: atomic write via temp file + move, with backup management — professional. But saves are manual (⌘S) plus scattered after-action silent saves (timeline drags, analysis apply). There is no periodic autosave, no crash-recovery document, no version browser. A crash costs everything since the last save — the single largest gap to the benchmark class.
  • Undo: deep and tested in the script editor (with perf guards); present in scene connections; absent nearly everywhere else (shot edits, production tables, vision wall, curation picks). The benchmark apps offer app-wide undo without exception.
  • Unit tests: 1,726 across six targets. Deepest: script editor, assistant actions (16 suites, 46 golden transcripts), vision wall (invalidation contracts, scale tests, snapshot baselines), production package (141). Thinnest: curation, playback, settings.
  • UI automation: 20 real journeys (launch, typing, return-key, undo, project create, relaunch persistence, navigation stress) plus VoiceOver traversal and accessibility-identifier checks — a real distinguishing strength. Coverage is script/outline/timeline-centric; curation, playback, production, and assets have no journeys.
  • Perf guards: every verify run mounts all central views against the 300-scene project; the wall runs its 1,000-element scenario; the editor has regression ceilings. Numbers print to stderr for eyeballing.

Recommendations

P0Make work loss impossible

  1. Continuous autosave: debounced background saveSilently() on every isDirty transition (e.g. 5s quiet / 30s max), plus save-on-background and save-on-quit. The 111ms encode is already off the main path — the plumbing exists; this is wiring, not architecture.
  2. Crash-recovery journal: keep the last autosave in a sidecar (.recovery) and offer restore-on-launch after an unclean exit.
  3. App-wide undo, staged: start where edits are destructive and frequent — shot edits, production tables, curation picks — with a model-level command stack (the script editor already proves the pattern at scale).

P1Earn the "handles a blockbuster" claim end-to-end

  1. Proxy media pipeline: background-generate 720p proxies on media import; playback/curation switch automatically. This is the difference between "opens the project" and "plays the dailies" at Interstellar scale.
  2. Versions: timestamped project snapshots with a browse-and-restore sheet (daily + on-demand).
  3. Interchange out: EDL/FCPXML export of the shot list and stripboard-ordered CSVs — editorial and AD departments live on these.
  4. Sectioned Shot List: group the 3,600-row list by scene with collapse — dissolves the last O(N) list diff and matches how crews actually navigate.
  5. Telemetry: opt-in crash reporting and a performance HUD (the audit harness numbers, live).
  6. Test debt, targeted: UI journeys for curation (pick-a-take), playback (open-and-scrub), production (edit a budget line); unit suites for curation/playback view-models.

P2Feel like the class

  1. Command palette (⌘K) over every action the assistant can already perform — the action registry exists.
  2. User-remappable shortcuts with a Logic-style key-command editor.
  3. Global search across script, shots, scenes, assets, notes.
  4. Background export queue with progress in a unified activity view.
  5. Script revision tracking (colored revision pages, locked scene numbers) — the screenwriting-professional feature the editor is one model change away from.
  6. Watch-folder dailies ingest into curation, auto-matched to shots by naming pattern.

Missing features worth adding (capability, not repair)

  • Stripboard & call sheets — production data is already modeled; a stripboard view and PDF call sheets make Production a daily on-set tool rather than a planning one.
  • Review & approval loops — takes and boards shareable to the web portal with per-frame comments (§7 roadmap already sketches presence; this is the concrete first workflow).
  • Presenter mode — the wall's walk-the-wall pass (DC-0029) generalized: pitch any view full-screen, chrome-free.
  • Per-department views — saved filters over shots (camera, art, VFX) exportable as their own sheets.
  • Open-format guarantee — the project is already JSON; document it, version it, and publish a schema so pipelines can build on it. Resolve and FCP cannot offer this; it is a differentiator, not a catch-up.
